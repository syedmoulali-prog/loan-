# System Architecture & Technical Specifications
## Customer Loan Eligibility System

### 1. Architectural Overview
The Customer Loan Eligibility System is engineered using a multi-tiered, decoupled client-server architecture:
- **Presentation Layer (Frontend)**: React 18, Vite, React Router 6, Tailwind CSS, Recharts, and Lucide icons.
- **Service & Business Layer (Backend)**: Java 21, Spring Boot 3.3.5, Spring Security 6, Spring Data JPA, JJWT.
- **Data Persistence Layer (Database)**: MySQL 8.0+ / In-Memory H2 for automated integration test suites.

```
+-------------------------------------------------------------------+
|                        React.js Frontend                          |
|  (AuthContext, ThemeContext, Recharts, Responsive Multi-Role UI)  |
+---------------------------------+---------------------------------+
                                  | RESTful APIs over HTTP (JSON)
                                  | Authorization: Bearer <JWT>
+---------------------------------v---------------------------------+
|                    Spring Boot REST API Gateway                   |
|   JwtAuthenticationFilter -> SecurityFilterChain -> Controllers   |
+---------------------------------+---------------------------------+
                                  | DTOs & Validation
+---------------------------------v---------------------------------+
|                          Service Layer                            |
|  EligibilityEngineService, AuthService, LoanApplicationService    |
|  DocumentService, FinancialDetailsService, ReportService, Audit   |
+---------------------------------+---------------------------------+
                                  | Spring Data JPA / Hibernate
+---------------------------------v---------------------------------+
|                       Database Engine                             |
|  MySQL 8.0 Relational Tables, Foreign Keys, Indexes, Timestamps   |
+-------------------------------------------------------------------+
```

### 3. Configurable Eligibility Engine Mechanism
The loan eligibility calculation never relies on arbitrary hardcoded constraints. Instead, the engine dynamically queries active rules from the `loan_rules` table:
1. `MIN_AGE_YEARS`: Ensures customer meets age maturity requirement.
2. `MAX_AGE_YEARS`: Validates age ceiling during loan repayment term.
3. `MIN_MONTHLY_INCOME`: Verifies minimum verifiable disposable monthly income.
4. `MAX_DEBT_TO_INCOME_RATIO`: Restricts maximum total obligations against gross earnings.
5. `MIN_CREDIT_CATEGORY`: Evaluates applicant credit score tier (`EXCELLENT` > `GOOD` > `FAIR` > `POOR`).
6. `REQUIRED_DOCUMENTS_COUNT`: Confirms minimum verified supporting documents.

Outputs generated by engine:
- `ELIGIBLE`: All active rules satisfied with healthy financial indicators (Score >= 75%).
- `REQUIRES_REVIEW`: Borderline metrics (e.g. debt-to-income near threshold or pending documents).
- `NOT_ELIGIBLE`: Critical failures in income minimums or credit standing (Score < 50%).
